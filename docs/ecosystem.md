# Published database toolkit integration

TenantGuard composes the existing tools published by [zeeshanch](https://www.npmjs.com/~zeeshanch). Their published packages and repositories remain independently maintained; this milestone does not republish or modify them.

| Existing tool                                                                                                                     | TenantGuard integration                                                                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [tenant-audit 0.2.0](https://www.npmjs.com/package/tenant-audit) ([source](https://github.com/ZeeshiCh/tenant-audit))             | Exact pinned dependency. Audit invokes its published CLI for PostgreSQL and MySQL, retaining `TA-*` rule IDs and configured target mappings, including tenant-aware foreign key and unique-constraint findings. |
| [db-deploy-doctor 0.2.0](https://www.npmjs.com/package/db-deploy-doctor) ([source](https://github.com/ZeeshiCh/database-toolkit)) | Exact pinned dependency. Connected doctor invokes its published CLI for PostgreSQL, MySQL, MariaDB and SQLite, retaining `DD-*` readiness check IDs.                                                            |
| [db-schema-guard](https://www.npmjs.com/package/db-schema-guard)                                                                  | Complementary schema-change review tool; not automatically executed or included as a dependency.                                                                                                                |
| [db-backup-verify](https://www.npmjs.com/package/db-backup-verify)                                                                | Complementary backup verification tool; not automatically executed or included as a dependency.                                                                                                                 |

The published tools are CLI-first, so integration uses their installed binaries rather than private library imports. TenantGuard generates explicit temporary configs, disables discovery and upstream failure thresholds, enforces process/output/deadline bounds, and maps known JSON results into its report contract. Raw evidence and driver messages are discarded to avoid propagating connection details; use the original tools directly when their full detailed reports are needed. Unexpected versions or report shapes fail as incomplete inspection.

Native TenantGuard collectors add adapter-specific policy-template, privilege, transaction-capability and ownership checks for all six engines. They complement the shipped analyzers. MariaDB is not passed to tenant-audit 0.2.0, which explicitly rejects it. SQL Server and MongoDB use native collectors because neither pinned tool supports those engines. Reports expose missing relationship/readiness coverage rather than implying it exists.

Real integration tests execute the installed published tools, assert their rule IDs, and verify database data/file preservation. Packed-consumer tests install the CLI and both tools from actual package archives and run the installed command against real SQLite.
