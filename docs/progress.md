## Tenant provisioning and migration lifecycle milestone — November 7, 2026

Implemented @tenantguard/lifecycle with portable versioned state/store contracts, a bounded single-process reference backend and an explicit management controller. Suspension/resume, exact-version management checks and explicit operation-ID recovery are supported. Failed/interrupted operations remain inactive. Currently recorded completed commands return idempotently without replaying SQL; recovery never silently changes a recorded target. Core routing and registry snapshots now recognize provisioning and still reject all non-active statuses.

Management credentials are separate from runtime SELECT-only credentials. Transactional schema/data changes and verified activation commit together. Native pg request admission acquires its shared advisory fence inside the actual data transaction; management waits on the corresponding exclusive transaction lock. This avoids the lost-control-connection hole of an unrelated admission session and rejects cached active/old-generation routes throughout migration.

Execution phases use one extended-protocol statement per query, reject transaction escapes, expire native facades and refuse commit after caught/failed/unawaited queries.
